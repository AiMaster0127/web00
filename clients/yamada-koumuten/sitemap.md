# 情報設計（sitemap.md） — 山田工務店 コーポレートサイト

新規制作・5ページ。**検索から各ページに直接着地する前提**で設計する（トップから順に見てもらえる前提を捨てる）。
第一目的は「見積り問い合わせ（電話／フォーム）」、第二目的は「求人応募」。全ページから最短でこの2つに辿れる導線を敷く。

---

## 1. サイトマップ（URL設計）

新規ドメイン取得のため、将来URLが変わらないよう**拡張子なし・浅い階層**で設計する。
本サンプルは静的HTMLで納品するため実ファイルは `.html`。公開時にサーバ側で拡張子を隠す想定（下表の「公開URL」を正とする）。

| ページ | 公開URL | 実ファイル | 役割（1行） | 主要CTA |
|---|---|---|---|---|
| トップ | `/` | `index.html` | 会社の第一印象＋強みの提示＋各ページへの分岐 | 見積り相談・電話 |
| 施工事例 | `/works/` | `works.html` | 実力の証明。写真で信頼を担保し相談動機を作る | 見積り相談 |
| 会社概要 | `/company/` | `company.html` | 会社の実在性・信用（許認可・沿革・アクセス） | 見積り相談 |
| 採用情報 | `/recruit/` | `recruit.html` | 職人採用。仕事内容・条件・応募方法 | 応募（フォーム／電話） |
| お問い合わせ | `/contact/` | `contact.html` | 見積り相談・採用応募の受け皿（フォーム＋電話） | フォーム送信・電話 |

> お知らせ（CMS対象）は**独立ページを増やさず**、トップに「最新のお知らせ」枠を置き、
> `data/news.json` からJSで描画する。全件は同枠内で展開（件数が少ない工務店の実態に合わせ、
> 専用一覧ページは作らない＝更新されない空ページを生まない）。将来増えたら一覧ページ化を提案。

### 階層図

```
/ (トップ)
├─ /works/    施工事例
├─ /company/  会社概要
├─ /recruit/  採用情報
└─ /contact/  お問い合わせ（フォーム）
     └─ /contact/thanks/  送信完了（thanks.html・noindex）
お知らせ … トップ内セクション（data/news.json をJS描画）
```

## 2. 各ページの役割・載せる情報・着地ユーザー

### トップ `/`
- **着地ユーザー**: 「三条 工務店」「新潟 注文住宅」等で検索した見込み客、社名指名
- **ファーストビュー**: 地域名＋事業＋強みが一目で分かるコピー＋見積りCTA＋電話
- **構成**: FV → 選ばれる3つの理由 → 事業内容（注文住宅／リフォーム）→ 施工事例抜粋（3件）→ お知らせ → 会社概要抜粋＋地図導線 → お問い合わせCTA
- **導線**: 各ブロックから該当詳細ページへ。FVと最下部に見積りCTA

### 施工事例 `/works/`
- **着地ユーザー**: 施工の質を見たい見込み客（最も相談に近い）
- **構成**: 導入文 → 事例カード一覧（写真・種別・エリア・一言）→ 見積りCTA
- **注意**: 写真はクライアント支給の差し替え前提。顧客名は出さない（エリア・種別のみ）。捏造しない

### 会社概要 `/company/`
- **着地ユーザー**: 発注前に会社の実在性・信用を確かめたい人、取引先、求職者
- **構成**: 代表挨拶（社長が担当する姿勢）→ 会社情報テーブル（名称・所在地・電話・営業時間・定休日・創業・建設業許可）→ 事業内容 → アクセス（地図）
- **注意**: 建設業許可番号は**要確定**（「許可あり」のみ支給）。番号は伏せてプレースホルダ

### 採用情報 `/recruit/`
- **着地ユーザー**: 地元で職人・現場スタッフの仕事を探す人
- **構成**: 働く環境の紹介（下請け丸投げしない＝自社施工で技術が身につく）→ 募集要項テーブル → 応募方法（フォーム／電話）
- **注意**: 職種・給与・勤務時間・休日は**仮置き＋確定要**。性別・年齢の募集制限は書かない

### お問い合わせ `/contact/`
- **着地ユーザー**: 見積り相談・採用応募の意思が固まった人
- **構成**: 電話（最優先・タップ発信）＋営業時間 → フォーム（問い合わせ種別で分岐）→ 個人情報の扱い一文
- **送信後**: `/contact/thanks/`（noindex）

## 3. 導線設計（グローバルナビ／CTA）

- **グローバルナビ（全ページ共通・単一ソース）**: トップ／施工事例／会社概要／採用／お問い合わせ
  - ナビ右端に**電話番号**と「見積り相談」ボタンを常設（PCヘッダー固定・SPは追従フッターバー）
- **パンくず**: トップ以外の全ページに設置（`ホーム > ページ名`）。構造化データ（BreadcrumbList）も付与
- **フッター（全ページ共通）**: 会社情報・ナビ・電話・お問い合わせ・コピーライト
- **SP（375px〜）**: 画面下部に「電話」「見積り相談」の追従バー。親指で届く位置にCV導線

## 4. CMS要否の判断

| 対象 | 更新頻度 | 判断 |
|---|---|---|
| お知らせ | 月1回程度・社長本人 | `data/news.json` 編集方式（静的）。WordPress不採用。セキュリティ更新責任を負わせない |
| 施工事例 | 数ヶ月に1回・写真差し替え | 静的HTML。更新は保守で対応（＝保守契約の口実／ストック収益） |
| その他ページ | ほぼ更新なし | 静的HTML |

**結論**: フルCMSは不要。お知らせのみデータファイル方式。これがクライアントの「お知らせだけ自分で更新したい」に過不足なく一致し、半年後に死なない構成。

## 5. SEO・技術要件（全ページ共通で担保）

- 全ページ固有の `<title>` / `meta description` / canonical / OGP
- 構造化データ: 全ページ `LocalBusiness`（＝工務店の実体）、トップに合わせて `WebSite`、下層に `BreadcrumbList`
- `sitemap.xml` / `robots.txt`（本番は全体公開、thanksのみnoindex）
- 375px〜レスポンシブ、キーボードフォーカス可視、`prefers-reduced-motion` 対応
- 日本語Webフォントはウェイトを絞る（もしくはシステムフォント優先で軽量化）
