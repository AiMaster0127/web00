# ヒアリングシート【HP用】

> クライアントにそのまま送れる形。専門用語を避け、選択肢を添えて聞く。
>
> LP（1ページ完結）案件では `hearing-sheet-lp.md` を使うこと。**聞くことが違う。**

---

## HPで最初に潰すべきこと

HPは **「会社・店舗の信頼を担保し、複数の訪問理由に応える基盤」** です。LPとは別の生き物です。

LPと違い、HPで案件を壊すのは以下の3つです。

- **更新の主体が決まらない** → CMSを入れるべきか判断できない。間違えると半年後に死んだサイトになる
- **既存サイトのURLを確認しない** → リニューアルで検索流入が消える。**最も損害賠償に近い事故**
- **関係者が多い** → 決裁者と窓口が違うと、修正が無限に増える

LPのヒアリングをそのまま流用すると、この3つを全部見落とします。

## 1. 目的

- **今回、サイトを作る（作り直す）きっかけは何ですか？**
  - [ ] 今までサイトがなかった
  - [ ] 古くなった・スマホで見づらい
  - [ ] 集客を増やしたい
  - [ ] 採用のため
  - [ ] 会社の信用のため（取引先・金融機関に見せる）
- **このサイトで、一番達成したいことは何ですか？**
- サイトを見た方に、してほしい行動は何ですか？（問い合わせ / 予約 / 求人応募 / 電話 / 資料請求）
  ※HPは複数あってOKです。ただし**優先順位**を教えてください

## 2. ページ構成

- **どんなページが必要だとお考えですか？**
  - [ ] トップ
  - [ ] 会社概要・店舗案内
  - [ ] サービス・事業内容
  - [ ] 料金
  - [ ] 実績・事例
  - [ ] お客様の声
  - [ ] スタッフ紹介
  - [ ] お知らせ・ブログ
  - [ ] 採用情報
  - [ ] お問い合わせ
  - [ ] よくある質問
- 上のうち、**なくても困らないもの**はどれですか？

> 📌 **制作側の判断メモ**
> ページは多いほど良いわけではありません。**更新されない空のページは信頼を毀損します。**
> 「あった方がいい」ではなく「運用され続ける」ページだけ作ること。

## 3. 更新（CMSの要否が決まる）★HP固有の最重要項目

- **公開した後、ご自身で内容を更新されますか？**
  - [ ] する
  - [ ] しない（更新は都度お願いしたい）
  - [ ] お知らせ・ブログだけ自分で書きたい
- するなら、**どのくらいの頻度で、どなたが**更新しますか？
- パソコンの操作は得意な方ですか？（WordPressの管理画面などを触れそうか）

> 📌 **制作側の判断メモ**
> - **更新しない** → 静的HTMLで十分。速い・安全・保守費が安い
> - **月1回、お知らせだけ** → 静的 + 更新代行。**むしろ保守契約の口実になるので有利**
> - **週1以上、複数人** → CMS（WordPress / microCMS）
>
> **安易にWordPressを入れないこと。** CMSはクライアント側にセキュリティ更新の責任が発生します。
> それを説明せずに入れるのは無責任です。

## 4. 既存サイト ★事故要因

- **今のサイトのURLを教えてください**（ある場合）
- 今のサイトは、**どなたが作りましたか？** 連絡は取れますか？
- **今のサイトで、検索から人が来ているページはありますか？**
- Googleアナリティクスなどのアクセス解析は入っていますか？　**管理画面を見せていただけますか？**
- 今のサイトの、**ドメインとサーバーの契約者はどなたですか？**
  - [ ] 自社で契約している（ID/パスワードあり）
  - [ ] 前の制作会社が管理している
  - [ ] わからない

> 📌 **制作側の判断メモ**
> - 「前の制作会社が管理」「わからない」→ **ここが最大の地雷。** ドメイン移管に数週間かかることも、連絡が取れず移管不能なこともある。**工数と納期に必ず織り込む**
> - 既存の全URLを洗い出し、301リダイレクトの対応表を作る。**これを飛ばすと公開翌日に検索流入が消えます**

## 5. 会社・店舗の情報

- 正式名称・所在地・電話番号・営業時間・定休日
- 設立年 / 沿革
- 代表者名（掲載しますか？）
- 資格・許認可・加盟団体はありますか？（建設業許可、宅建、医療法人など）
- 事業内容を、正確に教えてください

## 6. 訴求

- 同業他社ではなく、御社を選ぶ理由は何ですか？
- **実績を数字で教えていただけますか？**（年数 / 件数 / 取引先数）
- 主な取引先を掲載できますか？　**先方の掲載許可は取れていますか？**
- 実績・事例を載せる場合、**顧客名を出せますか？**（実名 / 匿名 / 不可）

## 7. 採用ページを作る場合

- 募集職種・雇用形態
- **給与・勤務時間・休日を掲載できますか？**
  ※隠すと応募が減ります
- 応募は、フォーム / 電話 / 求人サイト経由のどれですか？

> 📌 **制作側の判断メモ**: 性別・年齢による募集制限は法令違反。原稿に混入させないこと。

## 8. 素材 ★揉めやすい

- **写真はご用意いただけますか？**（あり / なし / 一部）
  ※HPはLPより必要枚数が多い。外観・内観・スタッフ・実績…と積み上がる
- ロゴのデータはありますか？（ai / svg / png / 名刺しかない）
- 会社案内やパンフレットの**データ**はありますか？（原稿の元になります）
- **原稿はどちらが書きますか？**（クライアント / こちら）
  ※HPは原稿量がLPの数倍。ここを曖昧にすると赤字になります

## 9. 機能

- お問い合わせフォームは必要ですか？
- **問い合わせの種類は複数ありますか？**（一般 / 見積り / 採用 / 取材）
  ※種類ごとに項目が変わるなら工数が増えます
- 送信内容は、メールで届けば十分ですか？　一覧で見られる管理画面が必要ですか？
- 地図・SNS埋め込み・多言語対応は必要ですか？
- **将来的に追加したい機能はありますか？**（ブログ / 予約 / 通販）
  ※先に聞いておくと、構造を作り込みすぎずに済みます

## 10. 公開まわり

- 独自ドメインはお持ちですか？　新規取得が必要ですか？
- サーバーはどうしますか？（既存 / こちらで用意 / わからない）
- **公開後の保守（更新・バックアップ・不具合対応）はどうお考えですか？**
  ※ここで保守契約の話を必ず出す

## 11. 条件 ★必ず握る

- **納期はいつまでですか？** その日付の理由はありますか？
- ご予算はどのくらいでお考えですか？
- **修正は何回まででお願いできますか？**（標準2回）
- **今回の窓口はどなたですか？　最終的に決裁されるのはどなたですか？**
  ※HPは関係者が多い。社長・専務・現場でバラバラの指示が来ると破綻します
- 社内で確認が必要な方は何名いらっしゃいますか？
- 参考にしたいサイトはありますか？（URLと、どこが good か）
- 「こういうのは嫌だ」というイメージはありますか？

## 見積り前に必ず確定させる7項目

これが未確定のまま着手すると、ほぼ確実に赤字か事故になります。

1. **ページ数**
2. **更新の主体と頻度**（CMS要否が決まる）
3. **既存サイトのURLとドメイン・サーバーの管理者**
4. 写真素材を誰が用意するか
5. **原稿を誰が書くか**（HPは量が多い。最大の赤字要因）
6. 修正回数の上限
7. **窓口と決裁者は誰か**

## 危険信号

以下が出たら、見積りを上げるか、条件を書面化してから受けること。

- 「ドメインは前の業者が管理してます」→ 移管に時間がかかる。最悪、移管できない
- 「原稿はそちらでいい感じに」→ HPの原稿は数千〜1万字。**必ず工数に入れる**
- 「とりあえず10ページくらい」→ 根拠がない。更新されないページが生まれる
- 「社長にも見てもらってから」が初回に出る → 決裁者が別。修正回数を明記して握る
- 「今のサイトのアクセス数は分かりません」→ リニューアルで何を失うか測れない。**リダイレクトを慎重に**
- 「WordPressで作ってください」（理由なし）→ 更新するのか確認する。しないなら静的の方が良いと説明する
