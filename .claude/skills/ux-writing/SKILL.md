# UXライティング

**インターフェースの中の言葉は、装飾ではなく設計材料です。**
余白や色に払うのと同じ注意を、ボタンの2文字に払ってください。

言葉がUIに存在する理由はひとつ。**理解しやすく、それゆえ使いやすくするため**です。

## ボタンは動詞で書く

押した結果が分かる言葉にします。「送信」は、何が送信されるのか、押した後どうなるのかを語りません。

| ❌ | ⭕ |
|---|---|
| 送信 | 無料で相談する |
| OK | 削除する |
| 確認 | 予約内容を確認する |
| こちら | 料金表を見る |

**「こちら」「詳しくはこちら」は最悪です。** リンクテキストだけ読み上げるスクリーンリーダー利用者に、何も伝わりません。

## 動詞は最後まで同じものを使う

「公開する」ボタンを押したら、トーストは「公開しました」と出る。「投稿が完了しました」ではありません。

**インターフェースの語彙は、道案内の標識です。** 途中で言葉が変わると、別の場所に来たと誤解されます。

同様に、ページ内で「お問い合わせ」と「ご相談」が混在していたら、読み手は別の行動だと思います。**ひとつに統一してください。**

## ユーザーの語彙で名づける

システムの都合ではなく、**人が操作し、認識しているもの**の名前を使います。

| ❌ システムの言葉 | ⭕ 人の言葉 |
|---|---|
| Webhook設定 | 通知の管理 |
| レコードを登録 | 予約を追加 |
| バリデーションエラー | 入力を確認してください |
| 認証情報 | ログイン方法 |

賢く見せようとしない。**具体的である方が、常に、うまいことを言うより優れています。**

## エラーは謝らない

エラーメッセージの仕事は、感情表現ではありません。**何が起きたか**と**どう直すか**を伝えることです。

| ❌ | ⭕ |
|---|---|
| エラーが発生しました | メールアドレスに「@」が入っていません |
| 申し訳ございません。処理に失敗しました | 送信できませんでした。時間をおいて、もう一度お試しください |
| 入力値が不正です | 電話番号はハイフンなしで入力してください |

**曖昧なエラーは、ないのと同じです。** 「エラーが発生しました」は、ユーザーを手ぶらで放り出します。

エラーはインターフェースの声で話します。人間のふりをして謝らないでください。

## 空状態は招待状

データがない画面は、失敗ではなく**行動のきっかけ**です。

- ❌ データがありません
- ⭕ まだ予約はありません。「予約を追加」から最初の1件を登録できます

## フォーム

- **ラベルは必ず置く。** プレースホルダーをラベル代わりにしない（入力すると消えて、何の欄か分からなくなる）
- 必須・任意を明示する。**任意項目に「任意」と書く方が、必須に「必須」と書くより親切**なことが多い
- 入力例を添える（電話番号: 0250xxxxxxx）
- エラーは**その項目の隣**に出す。ページ上部にまとめると、どこを直すか分からない
- 送信後に何が起きるか予告する:「1営業日以内にご返信します」

## 送信ボタンの前の一言が、CVを変える

フォームを前にした人の不安は、たいてい入力項目ではありません。**押した後に何をされるか**です。

> 「しつこい営業のご連絡はいたしません」
> 「その場で費用が分かります。契約の義務はありません」

この一行があるかないかで、送信率が変わります。

## 書き方の基本

- **能動態**を初期値にする
- **センテンスケース**（文中の不要な体言止め・すべて大文字を避ける）
- 埋め草を入れない。「ぜひ」「まずは」「なんと」は大抵削れる
- 各要素にひとつの仕事だけ。**ラベルはラベル、例は例。こっそり両方やらせない**
- トーンはブランドと読み手に合わせる。丁寧すぎる敬語は、かえって距離を作る

## 確認の手順

1. ボタンの文言を全部拾い出す → 動詞になっているか、統一されているか
2. 「こちら」を全部探して潰す
3. エラー文言を全部拾う → 「何が」「どう直すか」があるか
4. フォームのラベルとプレースホルダーを確認 → ラベルが省略されていないか
5. 押した後に何が起きるか、書いてあるか
